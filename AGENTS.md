## Como rodar checks locais
```
bash -n ./jarvis                                # syntax do entrypoint
python3 -m py_compile 11_SCRIPTS/<arquivo>.py   # compile do script alterado
./jarvis help                                   # ver comandos disponíveis
./jarvis command-audit                          # core/help/catalog/smoke em sync
env JARVIS_NO_REPORT=1 ./jarvis smoke-test      # smoke sem gerar relatório
env JARVIS_NO_REPORT=1 ./jarvis safety-gate     # secret-scan + storage + quality
./jarvis release-check                          # bateria completa
```
Sempre rodar `command-audit` e `safety-gate` após mexer em comandos.

## Como adicionar um comando novo (com segurança)
1. Criar script em `11_SCRIPTS/<nome>.py` (Python stdlib only).
2. No script: respeitar `JARVIS_NO_REPORT=1` (preview sem escrever em disco).
3. Plugar handler em `11_SCRIPTS/jarvis_core.py`:
   - função `xxx_command(args=None)` ao lado de outros handlers.
   - `elif cmd == "<nome>":` no `main()`.
   - linha em `help_msg()`.
4. Atualizar `11_SCRIPTS/command_audit.py` (`CRITICAL_COMMANDS`).
5. Atualizar `01_SISTEMA/03_COMMANDS/COMMAND_CATALOG.md`.
6. (Opcional) Adicionar entrada em `11_SCRIPTS/cli_smoke_test.py::CHECKS` com
   `JARVIS_NO_REPORT=1` para evitar gerar relatórios no smoke.
7. Validar: `bash -n ./jarvis && py_compile + command-audit + safety-gate`.

Se `command-audit` reportar `FALHA`, o release-check vai falhar; ajustar antes
de prosseguir.

## Status real format obrigatório
Toda resposta de agente deve terminar (ou conter) blocos no formato:
```
STATUS REAL
- Created:
- Modified:
- Tested:
- Not validated:
- Production:        ← sempre "nada tocado / nada alterado"
```
Sem este formato, o output não pode ser considerado válido.

## Padrões de saída dos comandos
- Todo comando imprime, na 1ª ou 2ª linha, `Status real: <descrição>`.
- Toda saída termina com `Produção: nada alterado.` (ou equivalente).
- Comandos que geram relatório respeitam `JARVIS_NO_REPORT=1` e mudam para
  modo preview.

## Comandos de uso diário (cheat-sheet)
```
./jarvis project-status --project ALIAS         # status compacto
./jarvis project-cockpit --project ALIAS        # cockpit (status + missão + next)
./jarvis doctor --project ALIAS                 # diagnóstico read-only
./jarvis qa-sprint --project ALIAS              # gera mission de QA sprint
./jarvis goal-sprint --project ALIAS --goal "…" # gera mission com DoD
./jarvis browser-qa --project ALIAS             # gera mission de UI/browser QA
./jarvis final-gate --project ALIAS             # gera mission de validação final
./jarvis claude-mission-latest                  # preview da última missão
./jarvis mission-open-latest                    # path da última missão (1 linha)
cat "$(./jarvis mission-open-latest)" | pbcopy  # copia prompt p/ clipboard
./jarvis project-memory --project ALIAS         # exibe memória do projeto
./jarvis project-memory-update --project ALIAS --from-git --dry-run    # preview debrief
./jarvis project-memory-update --project ALIAS --from-file FILE --apply # grava debrief
```

```
./jarvis self-debrief --from-file /tmp/jarvis-claude-out.md --apply
./jarvis self-cockpit                                    # confirma debrief gravado
env JARVIS_NO_REPORT=1 ./jarvis safety-gate
env JARVIS_NO_REPORT=1 ./jarvis smoke-test
```
